# Prediction markets

Independent agents research and trade on one local SQLite exchange. Models can
use Qwen through vLLM or OpenAI. Kalshi supplies market definitions and status
updates; orders execute only on the agent exchange.

## Setup

Use Python 3.10 or newer, from the repository root:

```bash
source .venv/bin/activate
python -m pip install -e '.[analysis,dev]'
# Add Modal commands when needed:
python -m pip install -e '.[deploy]'
```

Credentials belong in the root `.env` or environment variables. The runtime
loads only that `.env` and never includes credentials in saved configuration.
See [detailed setup and provider configuration](docs/usage.md).

## Commands

Every command starts with `python -m prediction_markets`. An editable installation
also provides the equivalent `prediction-markets` command.

```bash
python -m prediction_markets run --config configs/openai.yaml
python -m prediction_markets resume 20260921T191329Z-7d0d9b6a
python -m prediction_markets download RUN_ID
python -m prediction_markets trace RUN_ID --agent agent-03
python -m prediction_markets export RUN_ID
python -m prediction_markets plot RUN_ID --combined
```

Run identifiers can be a run ID, a directory, or a `run.db` path. Trace, export,
and plot default to the newest local run when no identifier is supplied. Use
`COMMAND --help` for its flags.

- `trace --follow` watches committed activity in a live run.
- `export` creates `trace_export/` with actions, complete book snapshots, and raw
  first-pull market objects. It supports `--agent`, `--tool`, `--market`, `--start`,
  and `--end`; existing exports require a different `--out` directory.
- `plot` supports `--ticker`, `--agent`, `--start`, `--end`, and `--combined`.
  `--offline` uses previously cached Kalshi trades.
- `trace`, `export`, and `plot` accept `--segment current` to select only the
  latest continuation. The default `--segment all` includes inherited history.
  Time intervals are inclusive at `--start` and exclusive at `--end`.
- `resume` preserves the entire saved configuration and agent setup, copies the
  original market cohort, and refreshes its statuses. It creates a child run;
  closed or stale markets are not replaced. Parent artifacts stay unchanged.
- `download` retrieves the complete Modal directory, checks the database, and
  generates missing trace exports. `--out` names the parent runs directory;
  `--force` explicitly replaces an existing stopped local run.

## Repository layout

| Location | Responsibility |
|---|---|
| `prediction_markets/runtime/` | Experiment orchestration and daily schedule |
| `prediction_markets/agents/` | Agent loops, prompt, private history, and tools |
| `prediction_markets/exchange/` | Transactional matching and bookkeeping |
| `prediction_markets/markets/` | Initial selection and updates to the fixed cohort |
| `prediction_markets/integrations/` | Kalshi, Tavily, model APIs, and token counting |
| `prediction_markets/storage/` | Schema, run paths, snapshots, lineage, and downloads |
| `prediction_markets/analysis/` | Shared datasets, terminal traces, exports, and plots |
| `configs/` | Complete experiment YAML files |
| `deploy/` | Thin Modal CPU experiment and Qwen GPU serving entry points |
| `tests/` | Offline tests grouped by the same responsibilities |
| `docs/` | Architecture, detailed usage, and design notes |
| `runs/` | Local run artifacts, excluded from Git |
| `archive/` | Previous auction implementation; excluded from the runtime and tests |

Top-level modules such as `runner.py`, `export_trace.py`, and `plot_prices.py`
are compatibility entry points. Existing commands and imports still work; their
implementations live in the packages above. New code should use those packages.

See [architecture and migration details](docs/architecture.md).

## Run artifacts

```text
runs/RUN_ID/
├── run.db
├── run.log
├── run.lock                  # present in newer runs
├── trace_export/             # generated by export or download
├── price_comparison/         # generated by plot
└── kalshi_history_cache/     # generated when fetching plot history
```

The database format and artifact paths remain compatible with saved runs.
Analysis reads stopped archives without modifying them. Live readers include
committed WAL transactions and never assume an active database is immutable.

## Modal

```bash
modal run --detach deploy/modal_openai.py --config configs/openai.yaml
modal run --detach deploy/modal_openai.py --resume-from RUN_ID
python -m prediction_markets download RUN_ID
```

For a raw download without generating auxiliary files, pass an **existing parent
directory** to Modal:

```bash
mkdir -p ./runs
modal volume get prediction-markets-runs RUN_ID ./runs --force
```

The CPU experiment runner and the Qwen GPU server are separate deployments.
See [provider setup and persistence details](docs/usage.md).

## Verification

```bash
python -m pytest -q
```

Tests use temporary databases and mocked external requests. No trading experiment
or paid model deployment is required.
